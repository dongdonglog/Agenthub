# 项目对比与完成度

本文对照 AA（Answer Anything）与同类项目，并给出 AgentHub 到 v1.0 的验收清单。
AA 的结论来自其仓库文档（README、需求分析、概要设计）；其他项目只按公开定位比较，未逐项实测。

## 1. 和 AA 对比

两者都是「IM + pi 运行时」：消息受理、会话代、工作区、预写会话文件、pi RPC、投递。

| 维度 | AA | AgentHub |
|---|---|---|
| 通道 | 钉钉 | 飞书 + 钉钉 |
| 运行时 | pi 1.4.0 | pi 1.4.0 |
| 会话/工作区 | 会话代 + 工作区 + 会话文件 | 同左（`conv+generation`） |
| 批次 | 整批合并、会话内串行 | 批次冻结、单会话单运行 |
| 排队 | 会话内串行、会话间并行 | 并发上限 + 公平队列/老化 + 每会话限流 |
| 状态投影 | 表情状态 + 进度卡片 | 飞书卡片（可选停止按钮）；钉钉文本；无表情 |
| 附件 | 对象存储 + MCAP | 本地附件 hardlink 到工作区；钉钉附件未接 |
| 权限 | Profile、多角色、Secret 物化、运行门控 | 无按群权限；管理台 Token + CSRF |
| 管理台 | 在线/历史、Profile、Skill、MCP、审计、启停/重置 | 概览/会话/历史、Skill、MCP、定时任务、审计、队列/优先级 |
| 运维 | 部署/权限自检/保留清理 | 备份恢复、Prometheus 告警、tag 自动发版、双架构镜像 |
| 成熟度 | M1–M3 完成，M4 进行中，未生产验收 | v0.2.x，测试与 race 通过，真实 IM 未验收 |

结论：**AA 更深（权限、表情、MCAP、角色），AgentHub 更广（双通道、调度、定时任务、运维交付）。**

## 2. 和其他类别对比

| 类别 | 代表 | 强项 | 弱项 | 与 AgentHub 的关系 |
|---|---|---|---|---|
| 平台型 | Dify / Coze / FastGPT | 可视化编排、知识库、多租户 | IM 原生弱、本地工作区执行弱 | 我们是入口 + 执行，不是替代 |
| Agent 网关 | OpenClaw / Hermes | 本地执行、工具、会话 | 企业治理、IM 接入、运维 | 我们更像带治理的 IM 版 |
| IM 原生机器人 | 飞书/钉钉自带 | 入口最顺 | agent 能力弱 | 我们补执行与治理 |

## 3. AgentHub v1.0 验收清单

| 项 | 状态 | 说明 |
|---|---|---|
| 飞书真实链路（问答/附件/停止/重置） | ⏳ 待部署方验证 | 本机与容器 admin 测试已通 |
| 钉钉真实链路 | ⏳ 延后 | 按要求先不做 |
| 7×24 稳定性 | ⏳ 未做 | 需长跑观察内存与工作区清理 |
| 并发压测（10 会话） | ⏳ 未做 | 每并发约 100MB，按 `MAX_CONCURRENT_RUNS` 估算 |
| 备份 → 恢复演练（pi 镜像） | ⏳ 未做 | 脚本已有，未在 0.2.x 镜像上演练 |
| token 用量 | ✅ 已接 | pi `message_end.usage` 汇总进 `run_state` |
| 成本金额 | ⏳ 未做 | 只有 token，未按价格换算 |
| 模型 fallback | ⚠️ 不支持 | pi 无跨模型自动兜底；`FALLBACK_MODEL` 仅写入模型清单 |
| bash 安全限额 | ⚠️ 部分 | 依赖容器 CPU/内存/网络；无 per-session 隔离 |
| 多实例/高可用 | ⏳ 未做 | 长连接单实例 |
| 文档与迁移说明 | ✅ 已有 | README、部署、架构、运维、本对比 |

## 4. 何时选谁

- 需要钉钉深度权限、表情状态、MCAP、多角色：选 AA；
- 需要飞书 + 钉钉双通道、管理台、定时任务、公平调度、容器化交付：选 AgentHub；
- 只需要问答 + 少量工具：两者都偏重，轻量 Go loop 更合适。
