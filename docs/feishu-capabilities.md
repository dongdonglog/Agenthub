# 飞书能力矩阵

> 每条结论必须标注依据：**实测**（本项目真机验证）、**文档**（官方文档/SDK 说明）、**待确认**（尚未验证）。
> 未验证的能力不得写进用户可见文案，也不得作为唯一实现路径。

## 1. 接入

| 能力 | 结论 | 依据 | 备注 |
|---|---|---|---|
| 长连接（WebSocket）接入 | 已实现（SDK `ws`），无需公网入口 | 文档 + 实现 | 启动、鉴权失败重试、优雅关闭已实测；完整事件流需真实应用验证 |
| 事件 3 秒内确认 | 超时触发重推 | 文档 | 与钉钉 Stream 类似的语义 |
| 多实例事件分发 | **集群模式，只有一个客户端收到** | 文档 | 不支持广播 → 单实例或按会话分片 |
| 长连接支持回调订阅 | **不支持**（官方 README 表述） | 文档 | 卡片回调可能需要 webhook，**待实测** |
| 断线重连 | SDK 内置自动重连；服务侧再包一层指数退避 | 文档 + 实现 | 断线期间事件由飞书重推，需保证受理幂等 |

## 2. 消息

| 能力 | 结论 | 依据 | 备注 |
|---|---|---|---|
| 文本 / 富文本 post | 支持 | 文档 | post 需解析多层结构 |
| 图片 / 文件 / 音视频 | 支持，按 file_key 下载 | 文档 | 需 `im:resource` |
| 引用（quote） | **无钉钉式引用链**，只有 `parent_id` / `root_id` | 文档 | 需额外拉取父消息 |
| 合并转发 | 支持展示，解析复杂 | 文档 | v1 用占位 + 说明 |
| @机器人 | 群聊默认必须 @ | 文档 | 全量群消息需 `im:message.group_msg`（管理员审批） |
| 消息长度上限 | 待实测 | 待确认 | 先按 4000 字符分块 |
| 消息撤回 | 有事件 | 文档 | 不作为取消信号 |

## 3. 发送

| 能力 | 结论 | 依据 | 备注 |
|---|---|---|---|
| 回复指定消息 | `replyTo` / `parent_id` | 文档 | 目标撤回时需降级为普通消息 |
| 主动消息 | 支持按 chat_id / open_id 发送 | 文档 | 受机器人可用范围限制 |
| 文件 / 图片 | 先上传素材再发消息 | 文档 | 单文件上限待实测（预期 30MB） |
| 文本/富文本编辑 | 支持编辑已发消息 | 文档 | 仅文本/富文本 |
| 消息撤回 | 支持 | 文档 | 仅自己发送的 |

## 4. 卡片

| 能力 | 结论 | 依据 | 备注 |
|---|---|---|---|
| 交互卡片 V2 | 支持 | 文档 | 按钮需 `behaviors: [{type:'callback'}]` |
| 流式更新（cardkit） | 支持，服务端打字机 | 文档 | 更新频率上限待实测 |
| 卡片按钮回调 | `card.action.trigger` | 文档 | **长连接是否支持待实测** |
| 卡片更新 | `PATCH /im/v1/messages/:id` | 文档 | 需保存 message_id |
| 卡片降级 | 失败可回落文本 | 设计 | 核心不依赖卡片 |

## 5. 表情（reaction）

| 能力 | 结论 | 依据 | 备注 |
|---|---|---|---|
| 给消息添加表情 | 支持 | 文档 | `reaction_type.emoji_type` |
| 删除表情 | **只能删自己加的** | 文档 | 建议按 emoji 删，不保存 reaction_id |
| 可用 emoji 集合 | 待实测 | 待确认 | 六态需映射，可能不足 |
| 表情事件 | 有增减事件 | 文档 | 不用于控制语义 |

## 6. 身份与通讯录

| 能力 | 结论 | 依据 | 备注 |
|---|---|---|---|
| open_id / union_id / user_id | 三种 ID 并存 | 文档 | 会话键统一用 open_id |
| 读取用户信息 | `contact.v3.user.get` | 文档 | 需 `contact:user.base:readonly` |
| 部门与负责人 | 需额外权限 | 待确认 | 取决于租户授权 |
| 管理员标记 | 无直接字段 | 待确认 | 用白名单配置替代 |

## 7. 权限清单（申请时对照）

- `im:message`：接收消息
- `im:message:send_as_bot`：以机器人身份发消息
- `im:message.reactions:write_only`：表情
- `im:resource`：上传/下载素材
- `im:chat:readonly`：群信息
- `contact:user.base:readonly`：成员基础信息
- `im:message.group_msg`（需管理员审批）：读取群内全部消息
- 卡片：`card.action.trigger` 回调订阅

## 8. Spike 计划（M1 第一周）

| # | 验证项 | 方法 | 通过标准 |
|---|---|---|---|
| S1 | 长连接能否收到卡片回调 | 发一张带按钮的卡片，点击 | 1 秒内收到 `card.action.trigger` |
| S2 | 卡片流式更新频率 | 200ms 更新一次，持续 30s | 不被限流，或得到明确阈值 |
| S3 | reaction 可用集合 | 遍历候选 emoji 添加/删除 | 至少 4 个可用且可删除 |
| S4 | 文件上限 | 上传 10/20/30/50MB | 得到明确阈值与错误码 |
| S5 | 引用父消息 | 回复一条消息后拉取 parent | 能拿到正文与发送者 |

S1 不通过时的降级：停止按钮改走 webhook（需公网）或仅保留 `/stop`。

## 9. 已知限制对设计的影响

| 限制 | 设计影响 |
|---|---|
| 集群模式只投递一个实例 | v1 单实例；v2 按 chat_id 分片或改 webhook + 队列 |
| 无引用链 | 控制解析依赖 `parent_id`，拉不到就按普通消息处理 |
| 机器人只能删自己的 reaction | 状态切换用「按 emoji 删」，不依赖 reaction_id |
| 群消息需 @ | 默认 `require_mention=true`，避免申请全量权限 |
