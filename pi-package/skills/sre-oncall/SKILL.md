# SRE 值班诊断

## 原则

1. 先止血/影响面，再根因；不要先猜。
2. 只读优先；写操作必须人工审批。
3. 每个结论必须带证据：PromQL、LogQL、trace、K8s event、变更记录。
4. 不确定就写“不确定”，并说明缺哪个数据源。

## 流程

1. 读取告警/案件上下文（标题、服务、环境、时间、标签）。
2. 查服务目录与最近变更。
3. 查指标：错误率、延迟、饱和度、实例健康。
4. 查日志：错误关键字、异常堆栈、时间窗。
5. 查链路：慢调用、错误传播。
6. 给出：
   - 影响面
   - 证据表（查询/时间窗/结果）
   - 根因候选（概率）
   - 建议动作（标注是否需要审批）
7. 结束前生成交接或复盘草稿。

## 禁止

- 不要执行 `kubectl delete/apply`、重启、扩容、回滚、改配置。
- 不要把日志中的密钥、token、个人信息写进结论。
